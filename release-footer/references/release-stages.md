# 发布阶段配置与推断

## 配置来源与优先级

复用项目已有发布配置与版本解析机制。元数据可携带可选 `stage` 和 `stageLabel`，在元数据加载和版本校验通过后一起应用；不要让旧版本元数据的阶段覆盖当前构建。

1. 项目明确配置的 `stage` 优先于版本后缀。这样 `1.2.3` 可以显式显示 Alpha，或按维护政策显示 LTS。
2. 没有显式阶段时，按版本的预发布标识推断。示例：`1.2.3-alpha.2` → `alpha`，`1.2.3-beta.1` → `beta`，`1.2.3-rc.1` → `rc`，默认文字 `RC.1`。同时支持项目采用的 `dev`、`pre-alpha` 标识。
3. 版本解析确认没有预发布标识时使用 `stable`。构建信息（如 `+build.12`）不改变发布阶段。
4. 未知预发布标识（如 `preview`、`nightly`、`canary`）保留为自定义阶段，默认中性灰色；不要自动当作 Stable。版本缺失或无效时使用 Dev 或项目的明确开发状态。

版本语法遵循项目现有约定；模板的 `0.7` 仅为示例，不强迫项目改成三段式版本。推断完整语义版本时优先使用已有解析器，不为徽标单独引入依赖。不要从 Git 分支名或提交次数推测发布阶段。

## 内容、颜色与显示

- 标准阶段的默认内容和颜色见 [SKILL.md](../SKILL.md#发布阶段徽标)。`stageLabel` 可覆盖默认文字，例如 `RC.2` 或项目自定义状态；空白文字按未配置处理。RC 的序号仅取自版本或明确配置。
- 将阶段键用于 `data-stage`，将显示文字作为文本节点渲染。React/Vue 使用正常文本绑定，普通 HTML 使用 `textContent`；不要把元数据文字作为 HTML 注入。无障碍标签应与当前文字匹配，不保留硬编码的“alpha 版本”。
- 模板内置已知阶段配色；Dev、Pre-alpha、EOL 和自定义阶段使用默认灰色。若项目需要自定义颜色，通过受信任的项目配置覆盖 `--release-stage-color`，检查小号白字的对比度。
- 项目可设置 `showStableBadge: false`，仅在阶段为 `stable` 时隐藏徽标。需要隐藏任何阶段的徽标时可使用项目的整体显示开关。隐藏时移除整个 `release-footer__status` 节点，而不是保留空标签。
- LTS、Deprecated 和 EOL 必须来自明确的维护配置，不从版本数字或发布日期自动推断。Nightly 和 Canary 是发布通道，也可以作为自定义内容显示。

## 验证示例

| 版本与配置 | 预期徽标 |
| --- | --- |
| `1.2.3-alpha.2`，无显式阶段 | 绿色 `αlpha` |
| `1.2.3-beta.1`，无显式阶段 | 蓝色 `Beta` |
| `1.2.3-rc.1+build.12`，无显式阶段 | 橙色 `RC.1` |
| `1.2.3`，无显式阶段 | 绿色 `Stable` |
| `1.2.3`，`showStableBadge: false` | 无上标节点或残留间距 |
| `1.2.3`，`stage: "alpha"` | 绿色 `αlpha` |
| `1.2.3`，`stage: "lts"` | 青色 `LTS` |
| `1.2.3-preview.1`，无显式阶段 | 灰色 `preview` |
| `1.2.3`，`stage: "custom"`，`stageLabel: "Internal"` | 默认灰色 `Internal` |

在目标项目实际实现推断或渲染逻辑时验证这些行为。此 skill 的 HTML 文件是外观模板，本身不读取或推断发布元数据。
